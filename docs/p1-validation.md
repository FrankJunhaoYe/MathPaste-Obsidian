## P2 技术决策

宿主解析接口适用于接入验证，但本轮没有证据支持它作为全部保护规则的唯一来源。依据计划的失败分支，P2 改用 **`mdast-util-from-markdown@2.1.0`** 提供独立 CommonMark 结构和源码偏移；CodeMirror 用于公开编辑器接入、选区及事务。

依赖选择已检查官方仓库、npm 元数据、MIT 许可证和锁文件。该包提供 ESM 与浏览器入口，当前版本 2.1.0，npm 元数据最后更新于 2026-10-03。现有 esbuild 能打成浏览器 CommonJS 包，无额外运行时导入。CodeMirror state/view 版本与 Obsidian 类型包的 peer 要求一致；所有宿主模块继续 external，未升级原有依赖。此次新增依赖均为开发探针和验证使用，产品入口没有引入解析器。

自动测试已证明：

- 普通、引用、列表中的代码，行内代码、链接与块级 HTML 均有可回到原始文本的范围；LF/CRLF 均覆盖。
- 临时替换文本不改变原字符串，非 BMP 字符后的 UTF-16 偏移正确。
- 1 MB 文档解析覆盖至末尾代码块，浏览器打包无需 Node API。

运行 `node scripts/p1/benchmark.mjs` 的本机单次结果：10,026 字符约 **33 ms**，1,000,026 字符约 **1,525 ms**。这是 Node 中的独立解析调用耗时，不能当作 Obsidian 交互延迟或稳定性能保证；宿主树测量也不包含先前状态构造的全部耗时。

P2 仍须解决以下问题，才可推进产品接入：

- YAML 与数学区域扩展、Obsidian 特有结构、行内 HTML 包裹及不完整结构的保守保护；CommonMark 样例通过不等于这些规则通过。
- 配对、嵌套、交叉、重复转义、内部美元符号、部分选区、幂等性和最小修改集合。
- 大文本处理应避免同步阻塞编辑器：先确定工作量上限或异步方案，再实测；不能将 1.5 秒同步解析直接接入粘贴事件。
- 通用转换的宿主模式、命令可用性、事件清理、富文本、附件及图片分支均留待 P3–P5。

## 复现

在符合 `.node-version` 的环境中：

```powershell
npm ci
npm run check
# 父目录须已存在；目标必须是尚不存在的新目录，不能位于仓库内或包含仓库。
npm run p1:prepare -- D:\AppsData\MathPaste\P1-New-Source
# 实时预览准备方式；本轮未验收此模式。
npm run p1:prepare -- D:\AppsData\MathPaste\P1-New-Live --live-preview
node scripts/p1/benchmark.mjs
```

在 Obsidian 的仓库选择器中打开生成目录，由用户确认该测试库的信任提示。探针仅在专用标记存在时运行，创建 `P1-parser.md`、`P1-paste.md` 和 `p1-report.json`。等待自动检查结束后，在 `P1-paste.md` 复制首行完整文本（不含换行），粘贴到最后的 `PRIOR>` 后。检查报告的 `paste` 各字段与表中一致。重新加载已有结果的测试库会保留报告；完整重测请生成新目录。

探针与报告不应放入日常库。准备脚本拒绝已有目录，并解析父目录真实路径以阻止经 junction/symlink 写入仓库。`npm run check` 检查正式包不含探针、宿主模块 external、路径保护和独立解析可行性；11 个自动测试通过后，仍不能勾选产品功能验收。
