# MathPaste 需求说明

整理日期：2026-10-19。依据项目发起者提供的需求讨论整理。

## 1. 目标与状态

目标是在 Windows 版 Obsidian 中，将复制文本里的 LaTeX 数学定界符转换为 Obsidian 使用的美元符号形式。仅替换外层定界符，不翻译、重写或修复公式内部内容。

用户已明确：只在 Windows 使用；已提供包含 `\boxed`、`\bar`、`\left`、`\frac` 的公式示例。粘贴转换、手动命令和保护规则来自前期讨论中的第一版建议，本文件将其整理为拟定验收目标，后续可由用户调整。

当前工程和开发流程已初始化；按计划开始 P1，首轮结果见 [P1 验证记录](p1-validation.md)。转换产品功能尚未实现，只在独立测试库验证接口。

## 2. 第一版拟定范围

| 编号 | 需求           | 预期行为                                       |
| ---- | -------------- | ---------------------------------------------- |
| R01  | 行内公式       | 将成对的 `\(` 和 `\)` 替换为 `$`               |
| R02  | 独立公式       | 将成对的 `\[` 和 `\]` 替换为 `$$`              |
| R03  | 粘贴转换       | 在 Markdown 编辑器粘贴时转换本次插入文本       |
| R04  | 手动命令       | 有选区时仅转换选区，无选区时转换当前笔记       |
| R05  | 代码保护       | 代码围栏、缩进代码块、行内代码中的内容保持原样 |
| R06  | 已有公式保护   | 已有美元符号数学区域及其内部内容保持原样       |
| R07  | 内容保留       | 公式内部的命令、字符、空格、换行顺序不变       |
| R08  | 配对与撤销     | 不转换未配对的定界符；每次有效操作支持正常撤销 |
| R09  | 本地处理       | 转换不进行网络请求，不上传笔记或剪贴板内容     |
| R10  | 无变化时不写入 | 未找到可转换内容时不制造空编辑或额外撤销记录   |

## 3. 规则与建议默认行为

- 保留输入换行：原有多行 `\[...\]` 转换后仍为多行 `$$...$$`。
- 对原本同行的 `\[公式\]`，默认仅替换为 `$$公式$$`；自动插入额外换行不属于当前规则。
- 一段文本可包含多个行内和独立公式，并与中文、英文或普通标点混排。
- 不使用整篇盲目替换：先识别代码和已有数学区域，再处理可转换文本。
- 在代码区域内粘贴时保留原文；不能仅根据剪贴板自身判断上下文。
- 选区位于代码或已有数学区域时也应保留原文。局部选区的判断需参考完整笔记上下文。
- 遇到未配对、交叉、嵌套、重复转义等无法可靠判断的定界符组合，建议保持相关片段原样；精确解析规则在开发前确定并加入测试。
- 再次转换已转换文本，应与第一次结果相同。
- 不默认占用系统或 Obsidian 常用快捷键，由用户自行绑定。

## 4. 不包含的能力

- OCR、截图识别或根据渲染结果还原 LaTeX。
- 修复错误的数学公式或判断数学结论是否正确。
- 连接 ChatGPT、自动抓取聊天记录或调用模型。
- 全库扫描、批量修改其他笔记或更改系统剪贴板。
- 手机端、macOS 和 Linux 的兼容性承诺。
- 社区插件上架、自动更新或正式发行。

如果复制所得的文本已经丢失 LaTeX 源码，定界符转换无法还原原公式。

## 5. 开发基线与待补充信息

- 实测环境已记录：Windows 11 build 26200，Obsidian API/界面版本 1.14.4；测试库位置见 P1 记录。其他版本尚未验证。
- 从 ChatGPT 实际复制的纯文本样例，包含中文、多个公式和代码混排。
- 按计划采用一个自动转换开关、默认开启；命中时按纯文本插入、第一版单选区、跨行行内公式和歧义跳过，作为开发基线。
- 重复转义、部分选区和复杂 Markdown 结构的具体输入输出将在 P2 固化；当前没有标为通过的转换验收项。

仍待补充的样例和边界规则应在相应功能开发和验收前明确。
