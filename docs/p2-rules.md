# P2 转换规则与验证范围

日期：2026-10-22。此文在实现前固定纯逻辑输入输出，现已由自动测试核对；编辑器命令、粘贴事件和设置属于后续接入阶段。

| 验收    | 输入或场景                                                                 | 预期                                     |
| ------- | -------------------------------------------------------------------------- | ---------------------------------------- |
| T01–T03 | `\(x\)`、`\[x\]`、中文混排                                                 | 仅将两端分别改为 `$`、`$$`               |
| T07     | 多行独立公式、LF/CRLF、非 BMP 字符                                         | 主体、空白、换行逐字保留                 |
| T08–T10 | CommonMark 代码、已有美元数学、YAML                                        | 原样；使用完整文档上下文                 |
| T11     | 正常公式和受保护结构混排                                                   | 只转换安全公式                           |
| T12     | 再次执行                                                                   | 返回零修改                               |
| T13     | 空或纯空白、未闭合、嵌套、交叉、重复反斜杠、跨行行内公式、主体内未转义美元 | 相关组原样；其他独立且明确的公式仍可转换 |
| T13     | 相邻源公式 `\(a\)\(b\)`，或直接紧邻美元符号                                | 原样，避免生成混淆的美元连续串           |
| T14     | 部分公式选区、保护区域内的局部选区                                         | 零修改；扫描完整文档以识别外层结构       |
| T15     | 空文本、无公式、空目标范围                                                 | 零修改                                   |

补充保护采用保守策略：Markdown 链接、图片、引用定义整体跳过；含行内 HTML 的整个 Markdown 文本块跳过。Obsidian wiki 链接/嵌入、`%%` 注释及其未闭合后缀跳过。不完整链接、HTML 标签或反引号结构所在文本块保留。未闭合 YAML 开头保护至文档末尾；成对跨行美元数学整体保护，未闭合单美元符号保护当前行，未闭合多美元符号保护后缀。

配对以完整文档中的源定界符为依据。嵌套和交叉组整体不转换；未闭合行内组在换行处终止，不影响下一行独立公式。未闭合独立公式可能使后续片段含糊，因此保持该后缀。重复转义的源定界符不视为可转换标记。

纯粘贴规划先检查原文选区是否接触保护范围，再构造替换后的临时完整文档。只接受完全位于本次插入文本内的安全配对。没有可转换公式时不给出插入修改，由后续宿主保留默认粘贴；此逻辑不读取系统剪贴板。

同步处理上限采用全文 32,768 个 UTF-16 代码单元、单行 2,048 个代码单元及 2,048 个结构标记。任一超限即返回 `too-large` 和零修改，包括小选区所在的完整长文档。此限制优先保证不使用截断上下文；不承诺固定毫秒延迟。后续命令必须明确反馈限制，自动粘贴必须保持默认行为。更大文档的异步方案另行开发。

本阶段不把纯逻辑测试结果等同于 Obsidian 内的单次撤销、实际粘贴或实时预览验收。

## 实现与验证记录

- `src/context.ts` 返回受保护范围；CommonMark 和 YAML 使用独立解析器，不读取宿主内部状态。
- `src/converter.ts` 提供 `planConversion`、`planPaste`、`applyEdits`、`mapOffset` 和 `mapSelection`。转换返回原文 UTF-16 偏移中的最小定界符编辑；粘贴规划返回一次替换和最终光标。输入越界抛出 `RangeError`；解析异常返回 `unsafe-context` 和零修改。
- `tests/converter.test.ts` 覆盖 T01–T15 的纯逻辑、选区、粘贴规划、大小限制和 600 组确定性组合的幂等性；`tests/context-failure.test.ts` 验证解析失败不会退回盲目替换；`tests/core-bundle.test.ts` 验证浏览器打包不依赖宿主、Node 或数学渲染库。
- Node.js 24.13.0 / npm 11.6.2，`npm run check` 通过，总计 109 个自动测试。宿主 U01–U10 未在此阶段执行。

依赖沿用 `mdast-util-from-markdown@2.1.0`，新增 `mdast-util-frontmatter@2.0.1`、`micromark-extension-frontmatter@2.0.0`，均为 MIT、适配现有 ESM/esbuild 工具链。查阅了 [AST 扩展文档](https://github.com/syntax-tree/mdast-util-frontmatter) 与 [YAML 语法扩展文档](https://github.com/micromark/micromark-extension-frontmatter)；这两条稳定版本线的 npm 更新时间分别为 2023-09-14、2023-06-27。未升级原有依赖。数学扩展的评估发现会额外引入渲染库，因此未保留该依赖，美元区域改用保守扫描；最终 `npm audit` 为零已知漏洞。依赖锁文件已更新。

`node scripts/p2-benchmark.mjs` 在内存中构建并运行核心，不保存笔记或日志。本机单次测量如下，只表示 Node 中的调用耗时，不能替代编辑器响应测试，也不作为 CI 时间断言：

| 合成输入           | UTF-16 长度 | 结果                | 耗时     |
| ------------------ | ----------- | ------------------- | -------- |
| 约 10 KB 混合文本  | 9,600       | 转换 400 组         | 47.03 ms |
| 约 32 KB 普通文本  | 32,037      | 转换 1 组           | 16.63 ms |
| 约 1 MB 混合文本   | 1,008,000   | `too-large`，零修改 | 0.74 ms  |
| 大量未闭合行内标记 | 6,000       | `unchanged`，零修改 | 52.03 ms |

结构标记预算计数字符为方括号、反引号、星号、下划线、尖括号、波浪线和竖线。此限制及链接/行内 HTML 的整块保护会漏过部分本可转换的公式，属于已知保守取舍。大型文档也不会因只选中一小段而绕过全文限制。
