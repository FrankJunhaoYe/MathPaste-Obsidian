# MathPaste 开发计划（待审查）

版本：草案 v0.2（工程状态更新） · 日期：2026-10-19。

本计划供项目发起者审查。用户已另行授权初始化项目与开发流程，因此先建立空插件入口、构建和工程检查。产品行为建议仍待审查，公式转换、命令、粘贴和设置均未实现；尚未修改 Obsidian 配置或笔记库。

## 1. 本轮拟交付的产品

第一版目标是一个可在 Windows Obsidian 独立测试库安装的本地插件：

- 粘贴时将成对的 `\(...\)` 转为 `$...$`，将 `\[...\]` 转为 `$$...$$`。
- 一个手动命令：有选区时转换选区，无选区时转换当前笔记。
- 一个设置：自动转换粘贴内容，建议默认开启；关闭后仍可使用手动命令。
- 跳过代码和已有数学区域，保留公式内容，并能一次撤销一次操作。

仓库名为 `MathPaste-Obsidian`，插件显示名为 `MathPaste`，插件 ID 拟定为 `mathpaste`。沿用已选定的 MIT 协议。

第一版不包含全库批处理、OCR、模型 API、公式纠错、移动端适配、社区上架或自动更新。安装包交付与 GitHub Release 发布分开处理。

## 2. 建议采用的行为规则

下表是此次审查的重点。标为“建议”的细节尚未视为用户已确认的需求。

| 场景                           | 建议行为                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------- |
| 普通 Markdown 位置粘贴         | 仅转换本次插入文本中的完整公式，不修改笔记其他位置                               |
| 多行独立公式                   | 只替换定界符，保留内部内容和原有换行                                             |
| 同行独立公式                   | `\[x\]` 转为 `$$x$$`，不额外强制换行                                             |
| 手动命令                       | 有选区时仅转换完全包含在选区内的公式；无选区时转换当前笔记                       |
| 代码与已有公式                 | 依据笔记上下文和插入文本跳过代码围栏、缩进代码块、行内代码及已有美元符号数学区域 |
| YAML 属性、链接目标、HTML 区域 | 建议保守跳过；无法可靠判断的结构保留原文，不猜测                                 |
| 未配对、嵌套、交叉或重复转义   | 保留有歧义的片段；独立且可确认的其他公式仍可转换                                 |
| 行内公式跨行                   | 建议第一版保留原样，避免生成有歧义的美元符号公式                                 |
| 公式内部包含未转义美元符号     | 建议跳过该公式，避免转换后提前结束目标数学区域                                   |
| 多光标或多选区                 | 建议第一版不自动转换粘贴；手动命令提示仅支持单选区，不退回整篇转换               |
| 自动转换反馈                   | 成功时不弹窗；手动命令可简短提示转换数量或无匹配内容                             |
| 快捷键                         | 提供可绑定命令，不预设快捷键                                                     |

不对括号或方括号本身做替换。公式内的 `\boxed`、`\bar`、`\left`、`\frac` 等保持原样，普通中文、空白和标点保持不变。

### 富文本粘贴的取舍

建议第一版以剪贴板的 `text/plain` 内容为转换依据：

1. 存在可转换公式且无文件/图片载荷时，按转换后的纯文本插入。即使同时存在 HTML，也不从 HTML 还原公式。
2. 这意味着命中的粘贴可能失去仅存在于 HTML 中的字体、表格等富文本格式；纯文本中本来包含的 Markdown 标记仍保留。
3. 没有匹配公式、只有图片或文件、已有插件接管、上下文不明确时，不拦截默认粘贴。
4. 需要保留原有富文本粘贴行为时，可关闭自动转换，粘贴后执行手动命令；前提是插入文本仍保留源定界符。

这是明确的第一版取舍，需在审查时接受或调整，不能把它描述为完整支持富文本转换。如果剪贴板已经丢失 LaTeX 源码，本插件无法恢复原公式。

## 3. 技术方案

### 工程与模块

建议使用 TypeScript、Obsidian 官方插件 API、esbuild，以及 Vitest。参考官方模板建立工程，提交锁文件，运行时不引入服务端、AI SDK 或网络服务。

| 拟定文件           | 职责                                                                   |
| ------------------ | ---------------------------------------------------------------------- |
| `src/main.ts`      | 插件生命周期、命令注册、粘贴事件接入与清理                             |
| `src/converter.ts` | 识别安全配对并返回最小修改集合，不直接写入笔记                         |
| `src/context.ts`   | 识别代码、已有数学区域和其他受保护范围，结合完整笔记判断选区和粘贴位置 |
| `src/settings.ts`  | 一个自动转换开关的界面与持久化                                         |
| `tests/`           | 转换规则、保护范围、位置映射与事件分支的测试                           |
| `manifest.json`    | 插件元数据、桌面限定与最低版本声明                                     |

工程清单暂将最低 Obsidian 版本设为 `1.1.0`，`isDesktopOnly` 已设为 `true`；最低版本仍需根据实际 API 与宿主测试调整。这些是工程元数据，不代表已经验证 Windows 或其他桌面平台的兼容性。

### 转换过程

1. 读取当前笔记、目标选区或插入位置及剪贴板纯文本。
2. 手动转换依据完整笔记识别保护范围。粘贴时先构造替换选区后的临时文本，分析插入文本与前后文共同形成的结构，不实际写入文档。
3. 只接受完整落在目标范围、未接触受保护区域、无歧义的配对。
4. 只生成定界符的修改，保留公式主体；没有变化则直接退出。
5. 通过一次编辑事务应用修改并映射光标/选区；粘贴时将插入和转换作为一次用户操作。

不采用“先正常粘贴，再全篇替换”的流程。当前可用的官方接口包括 `editor-paste`、`Editor.transaction` 和 `registerEditorExtension`；一次撤销、事件顺序和解析上下文仍需在目标版本实测，不能仅凭接口存在认定已满足要求。

### 解析方案的前置验证

优先验证通过 CodeMirror 6 编辑器扩展取得文档解析上下文，识别代码等受保护范围；对临时插入文本使用对应解析能力，并单独处理数学定界符配对。不得依赖未公开的编辑器内部属性。

此路线是待验证的技术假设。阶段 P1 必须同时验证实际节点类型、完整文档覆盖情况和临时文本解析能力；若宿主解析器无法稳定复用，需记录证据并确定独立 Markdown 解析依赖，再继续 P2。不得把覆盖不完整的手写 Markdown 识别器当成已支持全部保护规则。

这些阶段表示依赖关系，不是固定工期承诺。真实复制样例与 Obsidian 测试库主要影响 P1、P4、P5；可先准备规则和纯文本测试，但缺少宿主验证时不能宣称插件已完成。

## 5. 验证计划

沿用 [验收清单](acceptance.md) 的 T01–T15、U01–U10，并在开发时补充下列具体输入输出。当前不勾选任何通过项。

- **内容正确性**：用户给出的完整公式、中文混排、多个公式、空白、LF/CRLF、非 BMP 字符，以及转换前后公式主体的逐字比较。
- **保护范围**：不同长度反引号、波浪线围栏、缩进代码、列表和引用中的代码、已有数学区域、属性和链接目标。
- **上下文边界**：只选中半个公式、选区起于代码中间、替换跨越代码边界、在已有数学区域粘贴、插入文本自身包含代码围栏。
- **歧义输入**：缺失闭合符、空公式、交叉/嵌套、重复反斜杠、美元符号价格、公式内部美元符号；先固定预期再实现。
- **编辑行为**：撤销前有其他输入时一次撤销只撤本次操作，重做一致，光标与选区映射正确，多光标不误触发全篇转换。
- **粘贴分支**：纯文本与 HTML 同时存在、有文件/图片、其他插件已处理、关闭开关、无匹配、不完整源码。
- **性能**：以约 10 KB 和 1 MB 的混合文本记录耗时，补测大量未闭合定界符，排查反复回溯；人工确认编辑器可响应。

工程已设置 `npm run typecheck`、`npm test`、`npm run build` 和统一门禁 `npm run check`。初始化测试只验证元数据、版本一致性与打包契约。CI 配置在 Windows/Linux 执行相同检查，仅检查、不发布；远程运行状态以对应 PR 的检查结果为准。P1 的关键接口与宿主验证仍未完成，自动检查通过后仍需宿主人工验收。

发布前的阻断问题包括：误改代码或已有公式、丢失公式主体、撤销失败、插入重复文本、吞掉图片/附件粘贴，以及未说明的富文本行为变化。

## 6. 交付物与范围边界

计划通过并完成开发后交付：

- 插件源码、构建配置、锁文件、MIT 许可证与自动测试。
- 对应版本的 `main.js`、`manifest.json`；只有需要样式时才提供 `styles.css`，并按版本维护兼容性记录。
- 中文使用说明：手动安装、启用、关闭自动转换、绑定命令、撤销、卸载和已知限制。
- 验收记录：版本、提交号、测试环境、结果和仍未验证的范围。

默认先在独立测试库安装。日常库安装、GitHub Release、社区插件申请均在对应步骤获得用户指示后进行。

计划草案与工程初始化变更通过开发分支和 PR 审查，产品行为建议仍待确认。协作细节见 [开发流程](../CONTRIBUTING.md)。

## 7. 审查时最值得确认的事项

1. 接受“自动粘贴转换 + 手动命令 + 一个开关”的第一版范围，自动转换默认开启。
2. 接受命中公式时按纯文本插入的富文本取舍，或要求第一版保留富文本行为。
3. 接受保留换行、歧义跳过、跨行行内公式跳过，以及第一版单选区限制。

以上默认值均为建议；提供实际 Obsidian 版本和测试库位置属于后续宿主验证的前置资料，不是审查这份计划的前提。
